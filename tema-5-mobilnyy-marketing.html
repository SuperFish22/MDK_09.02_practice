Мобильный маркетинг и адаптация сайта

Большая часть посещений сайтов в России приходится на смартфоны, а поисковые системы оценивают сайт в первую очередь по его мобильной версии (mobile-first индексация). Мобильный маркетинг — это стратегия работы с пользователем смартфона: быстрый сайт, удобные действия «в один тап», геосервисы, мессенджеры, QR-коды и push-уведомления.

Мобильная стратегия

Мобильный пользователь отличается от пользователя компьютера: он часто в дороге, с одной свободной рукой, на медленном интернете и хочет быстро совершить одно действие.

  • Ключевые действия: позвонить, построить маршрут, записаться, оформить заказ, написать в мессенджер.
  • Инструменты: адаптивный сайт, ссылки tel: и мессенджеров, карты (Яндекс Карты, 2ГИС), QR-коды на офлайн-носителях, PWA и push-уведомления, SMS и мессенджер-рассылки (только с согласия).

Скорость: Core Web Vitals

Core Web Vitals — три ключевые метрики пользовательского опыта, которые измеряют Lighthouse и PageSpeed Insights.

  • LCP ухудшают тяжёлые изображения первого экрана и блокирующие шрифты и скрипты.
  • INP ухудшают тяжёлые JavaScript-обработчики.
  • CLS вызывают изображения без размеров, баннеры и шрифты, которые «толкают» контент.

Адаптивная вёрстка

Основа — метатег viewport и медиазапросы. Подход mobile first: сначала стили для смартфона, потом расширяем для больших экранов.

<meta name="viewport" content="width=device-width, initial-scale=1">

/* базовые стили — для смартфона */
.cards { display: grid; gap: 16px; grid-template-columns: 1fr; }
body { font-size: 16px; }

/* от 768px — планшет */
@media (min-width: 768px) {
  .cards { grid-template-columns: repeat(2, 1fr); }
}
/* от 1200px — компьютер */
@media (min-width: 1200px) {
  .cards { grid-template-columns: repeat(4, 1fr); }
}

Чек-лист мобильного удобства

  • Нет горизонтальной прокрутки на ширине 360 px.
  • Основной текст — не меньше 16 px.
  • Области нажатия — не меньше 48×48 px, между ними есть отступы.
  • Телефон — ссылка <a href="tel:+74950000000">.
  • Правильные типы полей: type="tel", type="email", атрибут autocomplete — открывается нужная клавиатура и работает автозаполнение.

Изображения и загрузка

<img
  src="hero-800.webp"
  srcset="hero-480.webp 480w, hero-800.webp 800w, hero-1600.webp 1600w"
  sizes="(max-width: 600px) 100vw, 800px"
  width="800" height="450"
  alt="Мастер меняет колесо в автосервисе"
  loading="lazy">
  • srcset и sizes — смартфон загрузит маленькую картинку, а не версию для монитора.
  • WebP / AVIF — в 2–3 раза легче JPEG при том же качестве.
  • width и height — браузер заранее резервирует место, CLS не растёт.
  • loading="lazy" — для изображений ниже первого экрана; картинке первого экрана lazy не ставят.
PWAПрогрессивное веб-приложение (manifest + service worker) можно установить на главный экран, оно работает без сети и умеет отправлять push-уведомления — промежуточный вариант между сайтом и мобильным приложением.

Этапы работы:

  1. Разработать мобильную стратегию проекта
  2. Провести аудит мобильной версии в DevTools
  3. Измерить производительность (Lighthouse Mobile, Core Web Vitals)
  4. Адаптировать интерфейс и оптимизировать загрузку
  5. Провести повторные измерения и сравнить
  6. Сформулировать рекомендации
